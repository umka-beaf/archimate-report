# Версионирование: две независимые оси, один составной тег

🇬🇧 [English](VERSIONING.md) · 🇷🇺 Русский

---

Образ версионируется по **двум независимым осям**, и тег кодирует обе:

```
umkabeaf/archimate-report:5.10.0-1.1.0
                          └──┬─┘ └─┬─┘
                      версия Archi │
                                   версия проекта (собственный SemVer этого репозитория)
```

### Зачем два числа

Версия Archi (build-arg `ARCHI_VERSION`) говорит, какой апстримный релиз
[Archi](https://www.archimatetool.com/) зашит в образ — она меняется только
когда сама Archi выпускает новую версию.

Версия проекта — собственный [SemVer](https://semver.org/) этого
репозитория, независимый от Archi. Она нужна потому, что код самого проекта
тоже меняется — иногда вообще без обновления Archi. [Поддержка нескольких
моделей](MULTI_MODEL.ru.md) (`1.1.0`) — первый такой случай: та же версия
Archi, но принципиально другой набор функциональности. Без второго числа не
было бы способа отличить «5.10.0 без multi-model» от «5.10.0 с
multi-model» — оба легли бы под один и тот же тег.

Версия проекта бампается по milestone'ам (выпущенная фича, значимый фикс),
а не на каждый коммит — что именно изменилось в каждой версии, с явным
акцентом на значимые изменения (а не просто список коммитов), смотрите в
`CHANGELOG.md`.

### Публикуемые теги

| Тег | Значение | Мутабельный? |
|---|---|---|
| `:<archi>-<project>` (например `:5.10.0-1.1.0`) | Точная комбинация — эта версия Archi, эта версия проекта | Нет — используйте именно его для прода |
| `:<archi>` (например `:5.10.0`) | Последняя версия проекта, собранная под эту версию Archi | Да — сдвигается вперёд по мере выхода новых версий проекта под тот же релиз Archi |
| `:latest` | Самая свежая сборка вообще | Да |

Нужен конкретный, воспроизводимый набор функций — берите составной тег.
Устраивает «что бы ни было новее для Archi 5.10.0» — берите голый тег версии
Archi. `:latest` — для разовых/dev-целей, как и у любого другого образа.

### Трассируемость без чтения тега

Каждый образ также несёт стандартные OCI-лейблы
(`org.opencontainers.image.version`, `.revision`), выставленные в версию
проекта и точный git-коммит, из которого собран образ — `docker inspect
umkabeaf/archimate-report:latest` покажет, что именно запущено, даже если вы
всегда тянете только `:latest`.

### Где анонсируются релизы

- `CHANGELOG.md` — по одной записи на версию проекта, прямо в этом
  репозитории.
- [GitHub Releases](https://github.com/umka-beaf/archimate-report/releases) —
  та же версия, но с написанным человеком описанием того, что нового, а не
  автосгенерированным дампом коммитов. Именно здесь стоит искать
  человекочитаемое объяснение крупного изменения вроде поддержки
  нескольких моделей.
