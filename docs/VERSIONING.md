# Versioning: two independent axes, one combined tag

🇬🇧 English · 🇷🇺 [Русский](VERSIONING.ru.md)

---

This image is versioned along **two independent axes**, and the tag encodes
both:

```
umkabeaf/archimate-report:5.10.0-1.1.0
                          └──┬─┘ └─┬─┘
                     Archi version │
                                   project version (this repo's own SemVer)
```

### Why two numbers

The Archi version (`ARCHI_VERSION` build-arg) tells you which upstream
[Archi](https://www.archimatetool.com/) release is bundled — it changes only
when Archi itself cuts a new release.

The project version is this repository's own [SemVer](https://semver.org/),
independent of Archi. It exists because this project's own code changes too
— sometimes with no Archi bump involved at all. [Multi-model
support](MULTI_MODEL.md) (`1.1.0`) is the first example: same Archi version,
materially different feature set. Without a second number, there would be no
way to tell "5.10.0 with multi-model" from "5.10.0 without it" apart — both
would have collided under the same tag.

Project version bumps happen per milestone (a shipped feature, a
security-relevant fix), not per commit — see `CHANGELOG.md` for what changed
in each one, with the significant changes called out explicitly rather than
left to a raw commit list.

### Tags published

| Tag | Meaning | Mutable? |
|---|---|---|
| `:<archi>-<project>` (e.g. `:5.10.0-1.1.0`) | Exact combination — this Archi version, this project version | No — pin this one for production |
| `:<archi>` (e.g. `:5.10.0`) | Latest project code built against this Archi version | Yes — moves forward as the project ships new versions against the same Archi release |
| `:latest` | Most recent build, period | Yes |

If you need a specific, reproducible feature set, use the combined tag. If
you're fine tracking "whatever's newest for Archi 5.10.0", use the bare
Archi-version tag. `:latest` is for casual/dev use, same as with any other
image.

### Traceability without reading a tag

Every image also carries standard OCI labels
(`org.opencontainers.image.version`, `.revision`) set to the project version
and the exact git commit it was built from — `docker inspect
umkabeaf/archimate-report:latest` tells you precisely what's running even if
you only ever pull `:latest`.

### Where releases are announced

- `CHANGELOG.md` — one entry per project version, in this repository.
- [GitHub Releases](https://github.com/umka-beaf/archimate-report/releases) —
  same version, with a human-written summary of what's new, not an
  autogenerated commit dump. This is the place to look for a plain-language
  explanation of a major change like multi-model support.
